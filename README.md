## 3. 상세 요구사항 (Requirements)

### 📋 기능 요구사항 (Functional Requirements)
* **FR-01. 건강정보 등록**
  * **신규 레코드 추가 (UI 입력)**: GUI 화면을 통해 사용자의 사람 정보(식별번호, 이름, 생년, 성별)와 건강 정보(키, 몸무게, 추가 건강 정보)를 직접 입력받아 등록.
  * **중복 체크**: 신규 등록 시 이미 존재하는 데이터(식별번호 또는 중복된 개인 정보 등)가 있는지 검사하여 중복 등록 방지.
  * **환자식별번호 자동 생성**: 신규 레코드 추가 시 고유한 식별번호(ID)를 시스템 내부 로직에 의해 자동으로 발급 (예: `P2026-0001`).
  * **(선택) 엑셀 파일 일괄 등록**: 외부 엑셀 파일(CSV 등)을 업로드하여 여러 사용자의 건강 정보를 한꺼번에 시스템에 추가.
* **FR-02. 건강정보 조회 및 검색 (목록, 개인)**
  * **전체 목록 보기**: 시스템에 등록된 전체 사용자들의 건강 정보 리스트를 엑셀 표(격자, Treeview) 형태로 한눈에 조회.
  * **상세 검색하기**: 이름, 식별번호, 또는 특정 조건(BMI 상태 등)을 기반으로 원하는 사용자의 정보를 검색하여 상세 조회.
* **FR-03. 건강정보 수정**
  * **개인별 정보 갱신**: 등록된 특정 사람을 선택하여 키, 몸무게, 추가 건강 정보 등 변경된 내용을 수정하고 즉시 반영.
  * **BMI 자동 재계산**: 키나 몸무게가 변경될 경우, 연동하여 BMI 수치와 비만도 판정 결과를 자동으로 재계산하여 업데이트.
* **FR-04. 건강정보 삭제**
  * **레코드 제거**: 등록된 특정 사람의 건강 정보 및 사람 정보를 안전하게 선택하여 목록 및 영구 저장소에서 삭제.
* **FR-05. 건강정보 통계**
  * **통계 정보 산출**: 등록된 전체 데이터의 총 정보 수(인원수), 평균 키, 평균 몸무게, 평균 BMI 수치 등 요약 통계 정보를 연산하여 화면에 시각화 제공.

### ⚙️ 비기능 및 제약 사항 (Non-Functional Requirements)
1. **예외 및 오류 처리 (Robustness & Error Handling)**
   * **입력 값 검증 (Validation)**: 키/체중에 문자열이나 0 이하의 음수 입력 시 비정상 종료(Crash)를 방지하고, `messagebox`를 통해 경고 메시지 출력.
   * **파일 입출력 예외 방어**: 파일 권한, 용량 부족, 파일 손상 발생 시 `try-except` 구문으로 안전하게 예외 처리 후 기본값(빈 리스트 등) 반환.
2. **사용성 및 사용자 경험 (Usability & UX)**
   * **직관적인 피드백**: 데이터 C/U/D 및 파일 저장 성공 시 `messagebox.showinfo` 알림 팝업 제공.
   * **상호작용 편의성**: 표(Treeview)의 특정 행 클릭(`<<TreeviewSelect>>`) 시 입력 폼에 데이터가 자동 채워져 즉시 수정/삭제 가능.
3. **코드 품질 및 유지보수성 (Maintainability & OOP Principles)**
   * **역할과 책임의 분리 (SoC)**: 파일 입출력(`health_db.py`), 핵심 로직 (`health_logic.py`), GUI 시각화(`health_gui.py`) 모듈 철저 분리.
   * **객체지향 설계**: 데이터 구조와 연산은 클래스와 메서드로 캡슐화하여 재사용성 향상.
   * **가독성 및 문서화**: 주요 클래스 및 함수에 Docstring 및 주석 필수 작성.
4. **환경 및 제약 사항 (Constraints)**
   * 외부 GUI 라이브러리 설치 없이 파이썬 내장 `tkinter` 활용.
   * 원활한 모듈 import를 위해 모든 소스 코드는 정해진 동일 디렉토리 구조 유지.

## 5. 데이터 레코드 및 파일 구조

### 👤 건강정보 레코드 구조 (Data Record Schema)

| 필드명 (Key) | 데이터 타입 | 설명 (Description) | 예시 값 |
| :--- | :--- | :--- | :--- |
| `id` | String | 환자 고유 식별번호 | `"P2026-0001"` |
| `name` | String | 사용자의 이름 또는 식별자 | `"홍길동"` |
| `birth_year` | Integer | 출생 연도 | `1995` |
| `gender` | String | 성별 (남/여) | `"남"` |
| `height` | Float | 사용자의 키/신장 (단위: cm) | `175.0` |
| `weight` | Float | 사용자의 체중 (단위: kg) | `72.5` |
| `bmi` | Float | 계산된 BMI 수치 (자동 산출 및 소수점 둘째 자리 반올림) | `23.67` |
| `status` | String | 비만도 판정 결과 (저체중, 정상, 과체중, 비만) | `"과체중"` |

### 📁 지원 파일 포맷 상세 (4가지 저장 방식)

1. **JSON (`.json`)**: 딕셔너리 리스트 형태의 텍스트 구조. 사람이 읽기 쉽고 웹 표준과 호환 (표준 데이터 저장 및 웹/외부 연동).
2. **CSV (`.csv`)**: 쉼표(`,`)로 구분된 텍스트 행 구조. 첫 행 헤더 포함 (엑셀 일괄 등록 및 표 형식 관리).
3. **일반 텍스트 (`.txt`)**: 커스텀 구분자로 연결된 한 줄 단위 문자열 (가벼운 텍스트 기반 수동 로그 및 단순 저장).
4. **Pickle (`.pkl`)**: 파이썬 객체 구조를 바이트 스트림으로 직렬화 (프로그램 내부 객체 상태의 완전한 보존).

#### 💡 파일 형식 작성 예시

```json
// JSON 예시
[
  {
    "id": "P2026-0001",
    "name": "홍길동",
    "birth_year": 1995,
    "gender": "남",
    "height": 175.0,
    "weight": 72.5,
    "bmi": 23.67,
    "status": "과체중"
  },
  {
    "id": "P2026-0002",
    "name": "김영희",
    "birth_year": 1998,
    "gender": "여",
    "height": 162.0,
    "weight": 52.0,
    "bmi": 19.81,
    "status": "정상"
  }
]
```

```csv

```

